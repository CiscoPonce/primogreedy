# PrimoGreedy Agent

**PrimoGreedy** is an open-source, LangGraph-powered micro-cap equity research and paper-trading agent. Every market day, it scans small-cap stocks across **USA, UK, Canada, and Australia**, enforces a strict quantitative firewall against illiquid traps and blow-off spikes, reads real **SEC EDGAR** filings and **Form 4** insider trades, runs a structured multi-agent investment thesis debate, stages decisions behind a human **Review Gate**, and calibrates future searches from open and closed portfolio outcomes.

**Links:** [Website (`primoinvesting.com`)](https://primoinvesting.com) · [Live Hugging Face Space](https://huggingface.co/spaces/CiscsoPonce/PrimoGreedy-Agent) · [GitHub Repository](https://github.com/CiscoPonce/primogreedy) · [VPS Data API (`primogreedy-api`)](https://github.com/CiscoPonce/primogreedy-api)

> **Disclaimer:** PrimoGreedy is an automated research and paper-trading experiment for educational purposes only. Nothing generated by this project is financial or investment advice.

### How It Works at a Glance

1. **Scout (`src/discovery/`)** — Queries dynamic `yFinance` screeners (`EquityQuery`) + curated fallback pools + Brave Search trends across 4 markets, scoring candidates by liquidity, Form 4 insider net buying, and historical portfolio attribution weights.
2. **Gatekeeper (`src/agent.py` / `src/whale_hunter.py`)** — Enforces hard quantitative rules before any LLM call: `$5M–$500M` USD-normalized market cap, `$0.10–$30` share price, minimum volume and `$150k/day` dollar volume (UK-adjusted), primary exchange allow-lists (no OTC pink sheets), `<= 30%` short float, and a pump/blow-off guard.
3. **Analyst & Debate (`src/agents/debate.py`)** — Pulls live fundamentals, currency-normalized valuation snapshots, and SEC EDGAR 10-K/10-Q MD&A & Risk Factors; produces a **Graham** baseline, **Lynch** catalyst, **Munger** bear inversion, and **half-Kelly** sizing.
4. **Review Gate (`src/portfolio_tracker.py`)** — Stages verdicts on the VPS Watchlist (`INITIATE`, `PENDING`, `DISCARD`) and dispatches HTML email briefs via Resend. Trades only execute after explicit human acceptance.
5. **Attribution & Re-Evaluation Loop (`src/reeval_portfolio.py`)** — Benchmarks open and archived `closed_positions` against `IWM` and `SPY`, evaluates steep drawdowns (`<= -25%`) first during weekday re-evals, and feeds win/loss attribution back into discovery scoring and analyst prompts.

## Core Architecture (The LangGraph Engine)

The system is built on **LangGraph** following modern best practices (partial state updates, `Command` routing, `Send` parallel fan-out, checkpointing, `RetryPolicy`, and multi-agent subgraphs).

### Hunter Pipeline (`src/agent.py` / `src/whale_hunter.py`)

```
START --> initial_routing --> [chat] --> END
                          \-> [scout] --> [gatekeeper] --Command--> [analyst] --> END
                                              \--Command--> [scout]  (retry)
```

1. **Scout Node** — Discovers candidates via `yFinance` dynamic screeners + curated fallback lists + Brave Search trending, scores them with Form 4 insider buying and portfolio attribution adjustments (`score_candidate(..., use_attribution=True)`), and pops the best unseen ticker. Tickers pulled from Brave News are pre-validated so dead/zero-cap symbols are dropped before wasting a gatekeeper retry.
2. **Gatekeeper Node** — Strict quantitative firewall using the `Command` pattern for routing:
   - Market Cap: **$5M -- $500M in USD** (native GBP/CAD/AUD caps are FX-converted so UK/CA/AU micro-caps gate correctly)
   - Share Price: `$0.10` to `$30.00` (normalized from pence for UK), with `$150k/day` liquidity floor, primary exchange allow-list, `30%` short-float cap, and pump/blow-off guard
   - Zombie Filter: rejects unprofitable companies with < 6 months cash runway
   - Routes directly to `analyst` (PASS / retries exhausted) or back to `scout` (FAIL) via `Command`.
3. **Analyst Node** — Two modes controlled by `USE_DEBATE` env var:
   - **Single-LLM** (default): Senior Broker analysis via OpenRouter (5-stage live-filtered `:free` fallback chain) with structured `InvestmentVerdict` output and attribution calibration lessons (`get_attribution_lessons()`).
   - **Multi-Agent Debate** (`USE_DEBATE=true`): Three-agent Investment Committee subgraph (Pitcher → Skeptic → Judge) that produces a hallucination-resistant verdict.

   Both modes fetch **SEC EDGAR** 10-K/10-Q filings (US equities), call Finnhub tools for deep fundamentals, and compute **Kelly Criterion position sizing**.

   **Currency-safe fundamentals for ALL regions**: UK per-share metrics (EPS, book value, price, 52W range) are normalized from pence → pounds before the Graham Number math, and every analyst/debate prompt is fed a currency-labelled **value snapshot** (market cap, revenue, growth, cash, debt, cash/share, EV/Rev, current ratio, P/B, 52W range, insider ownership, margins). Non-US regions no longer get a bare news snippet — they get the same real fundamentals as US tickers, with Finnhub `.`-suffix guards removed so international symbols fetch their actual insider/news/financials data.

### Workflow Pipeline (`src/workflows/workflow.py`)

```
START --> [data_collection] --> [technical_analysis] --> [news_intelligence] --> [portfolio_manager] --> END
```

A linear 4-node pipeline for deep single-ticker analysis (used by `main.py` CLI).

### Multi-Agent Debate (`src/agents/debate.py`)

When `USE_DEBATE=true`, the analyst node runs a 3-agent LangGraph subgraph:

```
START --> [pitcher (Nemotron Ultra 550B)] --> [skeptic (Gemma 4 31B)] --> [judge (Dots3 Note) --> STRICT protocol] --> END
```

1. **The Pitcher** — Writes the strongest bullish thesis using only provided data.
2. **The Skeptic** — Challenges the bull case, flagging any fabricated claims.
3. **The Judge** — Synthesises the debate into a structured `InvestmentVerdict`, downgrading if fabrications were found. It uses a dedicated JSON model, retries empty/rate-limited calls, walks a fallback model chain, and as a last resort parses a plain-LLM JSON response before raising.

**Resilience**: the judge runs on an 8192-token cap and, on `429` rate-limit or empty/failed parses, moves to the next fallback model instead of retrying the exhausted one. In `src/llm.py`, `_live_free_models()` caches OpenRouter's live `/api/v1/models` `:free` catalog for 1 hour so retired slugs are skipped automatically, and `invoke_with_fallback()` rejects empty completions before returning. If every path fails, the debate raises and degrades gracefully to single-LLM analysis instead of crashing.

**Free models (OpenRouter `:free` tier, dynamically verified at runtime)**:
- **Pitcher**: `nvidia/nemotron-3-ultra-550b-a55b:free` (also default `STRUCTURED_MODEL` and head of `MODEL_CHAIN`)
- **Skeptic**: `nvidia/nemotron-3.5-super-vl:free`, then `baidu/ernie-5.5-flash-preview:free`, then `recursive/flint-v1.0:free`. A 2026-11-19 VPS probe showed these three return a real answer. Gemma was refused, Lightning came back empty, and the router was slow.
- **Judge**: `dots-studio/dots-3-note-preview:free` (dedicated JSON role)
- **Fallback chain (`MODEL_CHAIN` in `src/llm.py`)**: `nemotron-3-ultra-550b-a55b:free` → `gemma-4-31b-it:free` → `dots-3-note-preview:free` → `nvidia/nemotron-3.5-lightning:free` → `openrouter/free` router catch-all
- **Structured chain (`STRUCTURED_CHAIN`)**: walks `nemotron-3-ultra-550b-a55b:free` → `gemma-4-31b-it:free` → `dots-3-note-preview:free` → `openrouter/free` so framework fields survive rate limits.

Models are configurable via `DEBATE_PITCHER_MODEL`, `DEBATE_SKEPTIC_MODEL`, `DEBATE_JUDGE_MODEL`, and `STRUCTURED_MODEL` env vars.

### Parallel Region Orchestrator (`src/whale_hunter.py`)

The daily cron dispatches all 4 markets (USA, UK, Canada, Australia) **in parallel** via the LangGraph `Send` API:

```
START --> dispatch_regions --> [hunt_region: USA]       \
                          \-> [hunt_region: UK]         |-- region_results --> END
                          \-> [hunt_region: Canada]     |
                          \-> [hunt_region: Australia]  /
```

Each `hunt_region` invokes the full per-region subgraph (scout -> gatekeeper -> analyst -> email).

Supports **catalyst-triggered single-ticker mode** via `CATALYST_TICKER` env var (used by `repository_dispatch` from the VPS polling daemon).

## LangGraph Features Used

| Feature | Where | Purpose |
|---------|-------|---------|
| Partial state updates | All agent nodes | Nodes return `dict` with only changed keys |
| `Annotated` reducers | `src/core/state.py` | `candidates` and `candidate_scores` use `operator.add` |
| `Command` pattern | Gatekeeper nodes | Combines state update + routing in a single return |
| `Send` API | `whale_hunter.py` orchestrator | Parallel fan-out across 4 market regions |
| `InMemorySaver` | All 3 graphs | Checkpointing with `thread_id` for state persistence |
| `RetryPolicy` | All nodes | `max_attempts=3, initial_interval=2.0` for transient errors |
| `recursion_limit` | All `invoke()` calls | Set to 30 to prevent infinite loops |
| Structured output | Analyst nodes | `with_structured_output(InvestmentVerdict)` for validated verdicts |
| Subgraph | `src/agents/debate.py` | Pitcher/Skeptic/Judge multi-agent debate as nested graph |
| `@tool` decorator | `sec_edgar.py`, `finance_tools.py` | LangChain tool pattern for API integrations |
| `START` / `END` | All graphs | Modern entry-point API (no deprecated `set_entry_point`) |

## Key Modules

### The Interactive UI (`app.py`)
A Chainlit-powered chat interface.
- **`AUTO`** — Smart scan (yFinance screener + Brave trending)
- **`@Handle`** — Social scout from X/Twitter accounts
- **`PORTFOLIO`** — View the agent's paper trade track record
- **`BACKTEST`** — Run backtest on paper portfolio
- **Direct Ticker** — Type any ticker (e.g., `AAPL`) for an instant deep-dive

### The Morning Cron (`src/whale_hunter.py`)
Headless agent running as a **GitHub Action** daily cron. Hunts all 4 regions in parallel, evaluates candidates through the full pipeline, and emails HTML reports via Resend.

### Alpaca Paper Trading (`src/broker/alpaca.py`)
Optional **Alpaca Markets** integration for live paper trading of US equities:
- Submits market orders for **BUY / STRONG BUY** verdicts on US tickers — but only when a decision has been **explicitly accepted** (interactive Chainlit analysis, or an accepted watchlist item). The automated hunter/reeval never submit orders by themselves (see *Review Gate*).
- Calculates share quantity from Kelly position sizing and account equity
- Safety limits: minimum $1 order, maximum 25% of equity per position
- Records `order_id`, `fill_price`, and `broker_status` to VPS
- Dry-run mode when `ALPACA_ENABLED` is not set (logs but doesn't submit)

### Review Gate — `proposal.md` 3-layer framework (`src/portfolio_tracker.py`)
Every analysis the agent produces is stored as a structured **analysis** and staged on a **watchlist**; trades are only recorded after an explicit accept. This implements the framework's rule that *a signal starts a review — it never executes an order*.

- `submit_analysis(...)` — posts the Senior Broker's structured verdict (business, cash-flow, debt/liquidity, dilution, valuation **bear/base/bull + range + margin of safety**, risks, invalidation facts, macro, portfolio fit, `sources[]`, `data_quality`, `proposed_action`, `review_trigger`, `next_review_at`) and stages the ticker.
- Discovery (`whale_hunter`) maps verdicts to **INITIATE / PENDING / DISCARD** and records **no trade**.
- Re-evaluation (`reeval_portfolio`) maps held positions to **INCREASE / MAINTAIN / REDUCE / CLOSE**; only **MAINTAIN** refreshes the ledger automatically (WATCH, no order) — everything else waits for acceptance.
- `accept_decision(ticker, action=...)` / `dismiss_decision(ticker)` close the review; accepting writes the paper trade and links it (`paper_portfolio.analysis_id`).
- Accept/dismiss from the VPS dashboard **Watchlist & Reviews** panel, the Chainlit UI, or the API.

### VPS Data Layer ([`CiscoPonce/primogreedy-api`](https://github.com/CiscoPonce/primogreedy-api))
Optional **FastAPI + DuckDB** backend deployed on a VPS (behind Tailscale) that replaces local JSON files for persistence (the legacy `vps/` directory in this repository is deprecated — see `vps/README.md`):
- `seen_tickers` — Prevents re-analysing the same ticker (30 days for BUY/STRONG BUY, 14 days for AVOID/WATCH to allow re-evaluation)
- `paper_portfolio` — Records **accepted** paper trades with Kelly sizing, `status` (`active` / `delisted`), Alpaca order IDs, fill prices, and linked `analysis_id`
- `closed_positions` — Archives exited paper positions when `CLOSE` is accepted, preserving realized `exit_price` and `gain_pct`
- `analyses` — Structured 3-layer analyses (stage, verdict, valuation range, risks, invalidation facts, sources, data quality, proposed action, next review)
- `watchlist` — The review funnel: `active → accepted | dismissed`, keyed by ticker
- `agent_runs` — Operational metrics for LangSmith correlation
- **Live Dashboard** (`GET /dashboard`) — Chart.js-powered portfolio dashboard with summary cards, `IWM` & `SPY` benchmarks, verdict distribution, Kelly sizing chart, sortable trades, attribution breakdowns, seen-ticker feed, and a **Watchlist & Reviews** panel with accept/dismiss controls
- **Key endpoints** — `POST/GET /analyses`, `GET /watchlist`, `GET /portfolio/reviews`, `GET /portfolio/attribution`, `GET /portfolio/closed`, `PATCH /portfolio/{ticker}/status`, `POST /watchlist/{ticker}/accept`, `POST /watchlist/{ticker}/dismiss`, `GET /portfolio/summary`

The agent (`src/core/memory.py`, `src/portfolio_tracker.py`, `src/discovery/scoring.py`) auto-detects the VPS via `VPS_API_URL` and falls back to local JSON files (or neutral attribution) when unavailable.

### Closed-Loop Attribution & Drawdown Re-Evaluation (`src/discovery/scoring.py`, `src/prompts/senior_broker.py`, `src/reeval_portfolio.py`)
- **Attribution-weighted scoring**: Once `/portfolio/attribution` reports at least 5 priced positions, `score_candidate()` applies a bounded `-6` to `+6` score adjustment (`_attribution_adjustment()`) favoring historically strong setups and penalizing underperforming buckets.
- **Prompt calibration**: `get_attribution_lessons()` appends concise recent portfolio win/loss calibration context inside `get_analyst_prompt()`.
- **Drawdown-prioritized re-evaluation**: Weekday re-eval (`src/reeval_portfolio.py`) excludes `delisted` positions and sorts steep drawdowns (`gain_pct <= -25%`, then `>= +50%` gainers) via `_prioritize_trades_by_drawdown()` before applying `--limit`.

### Catalyst Polling Daemon (`vps/catalyst_poll.py`)
VPS-based systemd timer that polls every 15 minutes during US market hours for intraday triggers:
- **Volume spike** — Current volume > 3x average daily volume
- **Price move** — Intraday move > 10%
- **Insider filing** — New SEC Form 4 purchase for a tracked ticker

When triggered, fires a GitHub Actions `repository_dispatch` event to run the pipeline for that specific ticker.

### Grading Engine (`scripts/` + `src/core/online_eval.py`)
Automated quality assurance via LangSmith Evaluators, split into **offline** and **online** tiers:

**Offline Evaluators** (run on demand against golden dataset):
- `scripts/build_golden_dataset.py` — Curates 50 representative traces into a LangSmith Dataset
- `scripts/evaluators.py` — 5 custom evaluators:
  - **Catalyst Grounding** (LLM-as-a-Judge) — Scores whether claims are backed by data
  - **Company Identity** (LLM-as-a-Judge) — Catches "name-trap" hallucinations
  - **Format** — Validates headers, no duplicates, Kelly present for BUY
  - **Verdict Validity** — Ensures verdict is one of the 4 valid values
  - **Kelly Math** — Checks allocation is within [1%, 25%] bounds
- `scripts/run_evals.py` — Runs all evaluators against the golden dataset

**Online Evaluators** (run inline during every cron):
- `src/core/online_eval.py` — After each analyst verdict, the cheap evaluators (`format_score`, `verdict_validity_score`) run automatically and post results as **LangSmith feedback** on the run. Zero extra LLM cost.

**Annotation Queue**:
- WATCH, AVOID, and fallback-path verdicts are automatically tagged with `needs_review=true` in LangSmith metadata, so the team can filter and review edge cases in the LangSmith UI.

**Prompt A/B Testing**:
- `src/prompts/senior_broker.py` supports a `PROMPT_VERSION` env var to pin to a specific LangSmith Hub commit. Deploy two cron runs with different versions and compare results in LangSmith Experiments.

### SEC EDGAR Ground Truth (`src/sec_edgar.py`)
Fetches the most recent 10-K or 10-Q filing from SEC EDGAR for US equities and extracts two investment-critical sections:
- **Item 7: Management's Discussion & Analysis (MD&A)** — Management's own view of operations
- **Item 1A: Risk Factors** — Legally mandated disclosure of what could go wrong

Uses the EDGAR EFTS full-text search API with BeautifulSoup HTML parsing and `RecursiveCharacterTextSplitter` for section truncation. Injected into the analyst prompt as `{sec_context}` for non-US equities this is skipped gracefully.

### Structured Verdicts (`src/models/verdict.py`)
Pydantic model enforcing one of 4 verdict types:
```
STRONG BUY | BUY | WATCH | AVOID
```
Used via `llm.with_structured_output(InvestmentVerdict)` with a graceful fallback to plain text LLM output.

### Kelly Criterion Position Sizing (`src/models/kelly.py`)
Computes optimal position size from historical portfolio performance using the **Kelly Criterion**:
- Calculates win rate, average win %, and average loss % from VPS or local trade history
- Applies the Kelly formula: `f* = (win_rate / avg_loss) - ((1 - win_rate) / avg_win)`
- Uses conservative **half-Kelly** with verdict-based scaling:
  - `STRONG BUY` → 100% of half-Kelly
  - `BUY` → 70% of half-Kelly
  - `WATCH` → 30% of half-Kelly
- Clamped to **1% -- 25%** to prevent over-concentration
- Requires minimum 5 historical trades before activating (returns 0% otherwise)

Position sizing is computed **post-LLM** and injected into the `InvestmentVerdict` model, appearing in both the report output and the paper trade record.

## Quick Start Guide

### 1. Environment Setup
```bash
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
```

### 2. Configuration (`.env`)
```env
OPENROUTER_API_KEY=your_key       # LLM Inference (5-model free fallback chain)
FINNHUB_API_KEY=your_key          # Deep Fundamentals & Insider Data
BRAVE_API_KEY=your_key            # Web Search
RESEND_API_KEY_CISCO=your_key     # Email Reporting (Cron only)

# Optional: VPS Data API (TLS via Caddy on :8080)
VPS_API_URL=https://your-vps:8080
VPS_API_KEY=your_vps_key

# Optional: Alpaca Paper Trading (US equities only)
ALPACA_API_KEY=your_key
ALPACA_SECRET_KEY=your_secret
ALPACA_ENABLED=true

# Optional: Multi-Agent Debate
USE_DEBATE=true                   # Enable pitcher/skeptic/judge pipeline

# Optional: LangSmith Observability
LANGCHAIN_TRACING_V2=true
LANGCHAIN_API_KEY=your_key
LANGCHAIN_PROJECT=primogreedy

# Optional: Prompt A/B Testing
PROMPT_VERSION=latest             # Pin to a specific Hub commit hash for A/B tests
```

### 3. Launching the UI
```bash
chainlit run app.py -w
```

### 4. Running the Workflow CLI
```bash
python3 main.py
```

### 5. Running Unit & Logic Tests
```bash
PYTHONPATH=. python tests/test_discovery_improvements.py
PYTHONPATH=. python tests/test_value_improvements.py
```

### 6. Deploying the VPS API (optional)
Deploy the maintained standalone backend from [`CiscoPonce/primogreedy-api`](https://github.com/CiscoPonce/primogreedy-api) (replaces the deprecated `vps/` scripts in this repo).

### 7. Running Evaluations (optional)
```bash
python scripts/build_golden_dataset.py   # Build the golden dataset from LangSmith
python scripts/run_evals.py              # Run all evaluators
```

### 8. Deploying to Hugging Face Spaces
This repository includes a `Dockerfile`, YAML frontmatter (`sdk: docker`, `app_port: 7860`), and `.github/workflows/sync-hf.yml` to mirror `main` automatically when `HF_TOKEN` is set in GitHub Actions secrets. Set these **Space Secrets** in your Hugging Face Space settings:

- **Required:** `OPENROUTER_API_KEY`, `FINNHUB_API_KEY`, `BRAVE_API_KEY`
- **Optional:** `VPS_API_URL`, `VPS_API_KEY`, `USE_DEBATE`, `LANGCHAIN_TRACING_V2`, `LANGCHAIN_API_KEY`, `LANGCHAIN_PROJECT`

## The Philosophy

PrimoGreedy does not try to predict the future. It relies on strict **Benjamin Graham** math (`Intrinsic Value = sqrt(22.5 * EPS * BookValue)`) to establish a baseline Margin of Safety, then applies **Peter Lynch's** logic to find the catalyst and **Charlie Munger's** inversion to find the catch. It is designed to say **AVOID** far more often than it says **BUY**.
